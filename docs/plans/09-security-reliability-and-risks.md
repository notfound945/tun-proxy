# 安全、可靠性与风险控制

## 1. 权限模型

MVP 整体通过 `sudo` 运行：

- 只读取受信任的本地 YAML。
- 不支持插件、脚本钩子或配置内任意命令。
- 状态、锁和持久化文件由 root 所有并使用最小权限。
- 配置和状态路径拒绝不安全的符号链接场景。
- 日志不记录业务数据正文或 DNS 原始负载。

后续可把系统配置操作拆入最小权限 helper，网络核心降权运行，但不属于 MVP。

## 2. 系统命令安全

- 只调用固定绝对路径。
- 使用参数数组，不经过 shell。
- 校验接口名、CIDR、地址、端口和网络服务名。
- 所有命令设置超时。
- 记录退出码和受限长度的标准错误。
- 不复用 `HOME` 等通用环境变量存放运行状态。

## 3. 恢复安全

- 修改系统前先写恢复状态。
- 状态文件原子写入。
- `cleanup` 只操作仍匹配记录的对象。
- 恢复失败时保留状态文件。
- 输出精确人工恢复步骤，不自动执行宽泛删除。
- DNS 服务故障时优先恢复系统 DNS。

## 4. 网络与资源安全

- Fake DNS 只监听 loopback。
- 管理接口若实现，优先使用权限受控的 Unix Domain Socket。
- DNS 和真实出口均设置超时。
- 限制单源 UDP、总会话和并发 DNS 数量。
- 不实施 TLS 中间人。
- 为 TCP、UDP、Fake IP、DNS、缓冲池和日志设置上限。
- 达到上限时快速失败，不无限排队或分配内存。

## 5. 主要风险

### R1：指定接口绑定不符合预期

控制：Phase 0 使用真实 TCP、UDP 和 DNS 流量验证；未通过前不进入主体开发。

### R2：DNS 自递归

控制：真实解析只使用显式上游和接口绑定 Resolver，禁止调用默认系统 Resolver。

### R3：系统 DNS 或路由残留

控制：事务状态日志、信号处理、幂等 cleanup、启动时检测未恢复状态。

### R4：Fake IP 错误复用

控制：Mapping TTL 长于 DNS TTL、活跃引用、持久化和回收保护窗口。

### R5：gVisor API 变化

控制：固定版本、内部适配层、集成测试和升级检查清单。

### R6：UDP 会话泄漏

控制：空闲超时、最大会话数、每源限制和接口失效清理。

### R7：网段冲突

控制：启动前检查路由冲突，允许配置替代池，冲突时拒绝自动覆盖。

### R8：IPv6 旁路

控制：MVP 对 AAAA 返回 NODATA 并明确记录限制；后续单独实现完整 IPv6。

### R9：DoH/DoT 绕过 Fake DNS

控制：MVP 明确记录限制；后续通过默认路由接管或显式 DoH 策略解决。

## 6. 发布前检查

- 依赖许可证已记录。
- 配置示例不包含用户真实 DNS、接口或内部域名。
- README 明确说明需要 `sudo` 以及会修改 DNS 和路由。
- cleanup 已在异常场景验证。
- 日志默认不输出敏感业务内容。
- 二进制包含版本、commit 和构建时间。
- 已在目标 macOS 版本和 CPU 架构完成实机测试。
